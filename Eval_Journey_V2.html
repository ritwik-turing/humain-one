What this is

The Evaluate step of the developer journey, step 6 of 9. The surrounding flow is unchanged from V12.
Evaluation does not gate publishingThere is no pass bar and no platform minimum. Once a developer has run once, Submit for verification is available whatever the result. The loop has to earn its use by being useful.
A metric's place is decided by what it needs, not by how important it soundsThat single rule produces the whole setup screen. Checks that need only the run or only the reply are always on, because they work on a first upload from a developer nobody has met. Checks that need a written correct answer exist only where the category has a reviewed answer set. Checks that need the cases run again in altered form change the size of the run, so they are opt in with the cost on screen.
Safety is not optional, and that is a deliberate choiceSensitive data in the reply, harmful content, prompt injection and answer language read the reply and nothing else, so they cost nothing to generalise and there is no honest reason to make them a toggle. Two cases in this run prove the point: both pass every mechanical column and both would be invisible without them. A check the developer can switch off is not a guarantee the marketplace can make. Microsoft ships ten equivalent evaluators and tells every application type to include them.
Going in circles and stopping early are worth catching for freeThose two account for about a quarter of failures in published studies of agent systems, so the cheap mechanical checks pay for themselves before anyone writes a single test. They cannot tell you whether an answer was right, which is the other three quarters.
Correctness is the developer's judgementThey read what happened and write what went wrong in their own words. We group those notes and count them. We never suggest a fix, because we never see their code. Where a judge does score correctness, the number ships labelled as a signal rather than a measurement, because nobody has checked that judge against a human on this dataset yet.
The pack says what was not checkedEvery check is listed for the verifier with what happened to it, including the ones that did not run and why. Silence about a metric reads the same as a pass, which is how a certification gets torn apart.
In this releaseWhich cases failed and what the agent did step by step, the always-on mechanical and safety checks, a place to write what went wrong, those notes grouped and counted, what broke since last time including new safety flags, category scores where an answer set exists, optional extra runs with the cost shown, and a coverage statement for the verifier.
DeferredTurning notes into automatic checks, judge agreement against a human, slicing by category, and a shared library of checks. The numbers in this mockup are illustrative, including cost per case, which needs the real figure before it goes further.
