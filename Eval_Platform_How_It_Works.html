We built a machine that tells you what it did not check.

Any agent, any dataset, any input type. It runs, it scores, it groups what went wrong, and it turns your own words into checks that run forever. The part that makes it an evaluation platform rather than a score printer is the last one: it states its own coverage, every time.

If you say one thing to the team, say this. Every metric names the one thing it cannot work without, so whether it runs is answered per case, not per run. That single rule produces the setup screen, the coverage counts, the evidence pack, and the reason this works for an image agent and a text agent without changing a screen.

Read it top to bottom. Everything above the dotted line happens once per run. Everything below happens because a run produced something worth looking at.

The load bearing arrow is the dashed green one. A note you wrote on one bad case becomes a check that runs on every case forever. That is the difference between a report and a platform: the second run is better than the first because of what you did after the first.

A case is five things, and none of them is a question

The first version of this product assumed a question came in and an answer went out. Ritesh was right that this made us narrower than the platform underneath us. The fix was to stop describing agents and start describing cases.

There is no agent type in this picture, and that is the point. One dataset holds a pothole photo, a CCTV clip, an Arabic call recording, a scanned deed, a query result and a plain question, side by side. Adding a ninth input type is a data change. It is not a new screen.

A metric declares what it needs, so coverage is a count

This is the rule that produces everything else. Sort metrics by what they cannot work without, and the setup screen, the pricing and the honesty all fall out of the ordering.

Read the right hand column out loud in the meeting. Two metrics both reporting a healthy number can be standing on very different amounts of the run, and until this product nobody could see that. A metric that quietly covered 161 of 380 cases looked identical to one that covered all of them.

Prism does the running. We do the deciding.

Worth being precise about the boundary, because the team keeps asking what we are actually building versus what we are wrapping.

Prism has no opinion about whether your agent is good. Uday said it plainly: Prism does not have the domain knowledge to set a threshold. That gap is not a weakness in Prism, it is the space our product occupies.

Why it holds together as an evaluation platform

Silence is treated as a defect

Every check appears in the evidence pack with what happened to it, including the ones that did not run and the reason. A pack that omits a metric cannot be read, and that is how certifications get pulled apart.

The free checks run first

Step repetition is 15.7 percent of observed agent failures and mishandled termination another 12.4 in the MAST taxonomy. Both are visible in the trace alone, at zero cost, before any model is involved.

Judge scores are labelled as signals

A model grading a model is direction, not truth, until somebody checks the judge against a human. Until that agreement number exists, the pack says so rather than printing a confident percentage.

Evaluation does not gate publishing

There is no pass bar and no platform minimum. Once a developer has run once, submit is available whatever the result. The loop has to earn its use by being useful, not by being compulsory.

The second run is where the value is

Comparing a job to the one before it is the only way to know whether your fix worked. A case that started passing is a win. A case that stopped passing is the thing to look at first, and a new safety flag counts even when every column stayed green.

A note outlives the person who wrote it

The developer who spots a failure writes one sentence. That sentence becomes a versioned check with an agreement record, running on every future job. Knowledge stops leaving when people move teams.

What we have not solved

Batch size, how per batch results add back up, and what happens when a batch fails halfway are still open with Chandra. Judge agreement against a human has not been run, so every judge score carries that caveat. Automatic metric and threshold suggestions were considered with Uday and deliberately deferred past V1, because an unvalidated suggestion is a second thing to check rather than an answer.

The one sentence to close on

Every other tool tells you a score. This one tells you the score and how much of the run it is standing on, then turns the thing you noticed into a check that runs forever. That is the whole product, and it works for an image agent and a text agent without changing a single screen.
